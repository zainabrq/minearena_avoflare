## Required files and ownership
| File | Required content | Access |
|---|---|---|
| observations.csv | Run/session, patient/source, source_time, sequence, four observed values, units, available quality/missingness | runtime-equivalent features; only observed columns transmitted |
| ground_truth.csv | Same join keys, true pre-sensor four states, optionally target curves, independent event annotations | offline only |
| clinical_context.json | Authoritative context snapshots or references with version/cutoff and applicability; Patient Context service generates causal snapshot | available at origin only |
| run_manifest.json (alias scenario_manifest.json) | Batch/run IDs, configuration hash/version, seed(s), duration/sample interval, scenario and event labels, source start, patient/variant, generator version, parameter and artifact references | offline only |
| physiological_parameters.json or equivalent | Actual initial targets, variability, sensor settings, time constants/coupling if implemented, parameter units/ranges and external inputs | offline; only known priors through context allowed at inference |
| artifact_events.csv or equivalent | Run ID, fault ID/type/channel, start/end source seconds, configured severity/value, actual observed behavior | offline only |
| deterioration_events.csv or equivalent | Independent event IDs, physiological onset, end/recovery, severe endpoint and label definition; stable/artifact-only runs explicitly no deterioration | offline only |

Observed and true rows join uniquely on (run_id, source_time_s) with patient/variant consistency. If combined files contain multiple sessions, never join on patient ID/time alone. Time columns `timestamp_seconds` (verified validator) or `elapsed_seconds` (verified integrated reader) map to source_time_s. True aliases true_HR/true_RESP/true_SpO2/true_TEMP; target_HR etc are scenario target, not noise-free simulator truth and not substitutes. True physiology includes modeled AR variation, before sensor measurement noise. Check finite truth and bounds; missing observed value retains mask. For deliberate packet dropout, observed may omit ticks, but truth stays complete and dropout metadata explicitly accounts for unmatched truth rows. Distinguish source timestamps from wall receipt.

## Data leakage controls
Never use scenario_label, fault_type/active, deterioration onset/end, future target knots, true_vital fields, run_id, patient ID, source type, generated severity or hidden future activity in neural features. IDs only for joins/splits. Runtime quality cannot be copied from offline fault labels. Patient Context generated as-of prediction time, historical medication use unknown unless confirmed, no future Synthea diagnoses or discharge outcomes. Rolling baseline, expert interpretation, slopes and normalization computed causally. Fit normalization on training only. Split independent trajectories before sliding windows, held-out patients/configs where practical, no overlapping windows across partitions, no identical trajectories across splits. Preserve split registry. Use same clinical/manifest/encoder code in training and serving; fixed 15s frame, 5min history proposed, forecasts 5/15/30min as supported. A five-minute history + five-minute future needs at least ten minutes of appropriate source span plus any endpoint convention; longer forecasts need longer runs. No extrapolated labels beyond observed truth. Calibration not required for safety; training masks handle unestablished baseline.

## Batch acceptance and expansion
Run tools/validate_training_batch.py first. It checks physical file presence, schema aliases, unique run/time keys, finite true fields, patient consistency, missingness, durations, time joins, observed label leakage and exact-duplicate fingerprints. Its report does not prove clinical validity or semantic correctness. Review manifest seeds, scenario diversity, independent deterioration annotations, parameters, context cutoffs and fault/true separation manually. Existing MATLAB validate_batch_trajectories.m checks target variation and 40 runs; it is complementary, not sufficient. For initial hackathon use existing verified diverse 40 runs if sufficient span and no leakage, then add missing evaluation scenarios and multiple independent seeds/onset/severity variations. AI handoff's 800 trajectories/800 hours is planning estimate, not required minimum; don't block mandatory functionality on that scale. Prioritize held-out evaluation and meaningful diversity. Avoid fixed onset shortcut and one disease=one scenario mapping. Include stable, improvement, slow/rapid, intermittent, activity-related, respiratory, thermal, medication-context (only modeled assumptions), sensor and mixed scenarios. Use 70/15/15 as proposed run-level split, report actual counts, reserve some patient/config holdouts if feasible.

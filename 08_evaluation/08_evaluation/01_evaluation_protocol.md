# Evaluation protocol v1.0 — PS03
## Scope and frozen inputs
Mandatory PS03 §3.7 and evaluation criteria: lead time, alert efficiency, false alerts, FHIR compliance and explainability. V4.1 and clinical policy 07 section 6 govern implementation. Compare deterministic V4.1 pipeline first; report optional PINN-ODE ablation separately. Experimental forecasts cannot independently alter clinical priority.

## Input contract
Each run has observations.csv (source time, identity, observed four vitals, missingness and runtime-available quality evidence), clinical_context.json (as-of context), ground_truth.csv (offline true synthetic physiology, independently annotated events and faults), run_manifest.json (offline seed, generator/version, duration, scenario and hashes). Require unique run/session, monotonically ordered source-time for nominal runs; network fault tests intentionally alter delivery ordering without altering original source time. BIDMC separate identity; no synthetic temperature, no labelled deterioration claims. Actual clinical context should come from Patient KB, with synthetic overlays explicitly separate.

Ground truth event table: event_id, run_id, onset_s, severe_endpoint_s nullable, end_s, event_type (deterioration or sensor_fault), affected_vitals, annotation_rule_version. Define severe endpoints independently of tested alerts, using underlying synthetic physiological trajectory and a predeclared scenario severity criterion. Annotate onset and end before test; no post-hoc adjustment. Stable runs explicitly have no deterioration events. Record simultaneous fault/deterioration independently. Labels not available to either monitoring system. Expose only realistic device quality flags, not hidden injected fault IDs.

## Comparator (freeze before test)
Use fixed Scale 1 NEWS2 component bands from clinical spec 03, with same unit normalization and rounding. No context, rolling baseline, prediction, cross-vital or artifact suppression. Any component score 3 => Urgent; otherwise any score >=2 => Review; else Watch (or insufficient when none scored). Missing/null not scored; raw recorded zero HR/RR/SpO2 is evaluated as a low value for this intentionally naive comparator; do not manufacture zeros. Nonfinite/incompatible unit values not scored. Apply latest observations and same 15-source-second freshness policy; do not use future samples. Evaluate comparator per received observation and proposed safety per observation, proposed routine per window. This favors comparator responsiveness rather than artificially delaying it. Log evaluation cadence for both. No fixed threshold tuned using held-out outcomes.

## Proposed system
Use implemented clinical rules 03–07 unchanged; actual policy versions logged. Adaptive windows and independent safety, baseline freeze, context authorization, artifact handling and alert lifecycle. Cold start must not suppress safety. Any optional model forecast is experimental unless validated; show enabled status and no model-only priority changes. Use same input frames and delivery order as comparator.

## Fair episode lifecycle
Both systems: open clinical episode at first qualifying Review/Urgent; retain same ID for escalation, repeated notifications and recurrence until resolution. Watch updates not counted. For offline reproducibility use a scripted authorized reviewer for both: after 60 contiguous source seconds of valid stable observations, no remaining trigger or safety floor under that system, log simulated clinician closure with reason. Missing/suspect readings cannot establish recovery; comparator has no artifact suppression, but missing values still prevent stable closure. No auto-close urgent in production. If genuine end-of-run occurs before recovery, leave episode open. Technical and uncertain verification episodes separately classified and counted; use same event matching conventions. Log clinical episodes that include verification, so artifact suppression cannot simply hide notification burden in another category. Report both clinical and total unique notification episode burden. Freeze this protocol before scoring. 

## Execution
Use held-out independent trajectories, not training or tuning runs. Split whole runs and ideally held-out patient configurations; never random overlapping windows. Log seed, split, code commit and config hash. Use stable warmup where appropriate (900 eligible seconds initial baseline), include separate cold-start deterioration tests. Identical observation inputs, timestamps, runtime context availability and network schedule for paired comparison; reset both state stores per run. Accelerated replay uses source seconds for clinical logic and exposure, monotonic wall-clock for processing latency. A fixed threshold evaluation cannot infer actual physiological onset from corrupted observations. Test one patient then ten concurrent; preserve isolation. Avoid comparing speed from separate hardware/configurations.

## Matching and reporting
Match each event to first qualifying clinical Review/Urgent alert triggered at or after onset and at/before predeclared event end. An episode already open at onset counts only if a new qualifying evidence update after onset is attributable to that event; report separately as pre-existing alert, never backdate detection. Use one-to-one earliest eligible matching, no duplicate credit; for overlapping events declare matching attribution before evaluation. Unmatched clinical episodes are false alerts under synthetic labels; report unmatched verification and technical separately. Late alerts after severe endpoint but before event end have negative lead time; events without endpoint use detection delay only. No alert => missed; never substitute zero or event duration for missed lead time. See 03.

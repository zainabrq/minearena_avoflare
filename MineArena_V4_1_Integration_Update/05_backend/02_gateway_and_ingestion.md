# 02 | Secure gateway and ingestion

## Producer interfaces
Both MATLAB virtual wearable and BIDMC replay submit FHIR R4 Vital Signs Observation resources via the same authenticated ingestion operation. Reuse teammate's actual FastAPI route and adapter. Prefer individual observation submission at the nominal sample interval or a supported batch whose observations each retain identity and timestamps; safety must inspect each event, not an averaged packet. If batch collection adds delay, measure it and do not claim per-sample latency target. Synthea profile import is an authorized clinical-data operation, not a live vital stream. Patient symptom/task input uses a separate authorized operation, not fabricated vital observations.

Logical producer envelope (map to final contract): producer ID, source namespace, patient/subject ID, variant, session, event ID, sequence when available, signed transmission timestamp, source timestamp/offset, FHIR resource and integrity metadata. Credentials/signatures can be transport headers. No custom envelope may replace valid FHIR resource acceptance; use existing ingestion route plus authenticated metadata as agreed. Never accept client-supplied identity without server mapping. Use stable event identifiers across retries.

## Validation order
- Limit request size, rate and supported content type; authenticate and verify authorization, signature and replay semantics.
- Validate FHIR resourceType, R4 Vital Signs structure, supported LOINC, UCUM, status, subject, effective time and quantity or dataAbsentReason. See 03. Reject structural/identity violations with safe error response. Do not drop physiological extremes merely because they are alarming.
- Preserve raw value, raw units, missingness, source timestamps and original resource; normalize only through explicit supported conversion with provenance. Zero is an observed value, not a null. NaN/Infinity cannot appear as JSON quantities. Distinguish missing, suspect, implausible and valid according to 03_clinical_intelligence/06_artifact_handling.md.
- Atomically deduplicate per authorized event identity and payload hash. Same ID/same hash is idempotent; same ID/different hash is conflict and audit. A legitimate retransmission may use a fresh authenticated transport nonce while retaining event ID. Never re-count or republish as a new clinical event.

## Event time
Preserve source physiological time and arrival/wall time separately. MATLAB uses scenario source-time; replay uses recording offset and derived effectiveDateTime with explicit replay provenance when no actual clock exists. BIDMC recording 23 starts at -1 seconds; preserve original offset and mapping. Never interpret historical replay timestamp as an authentication nonce timestamp. Session registration provides time origin, speed and expected sample rate; replay controls require authorization. Use event time for baseline/trend/persistence and wall time for ingestion latency and transport freshness. Pause/resume must not falsely advance physiological time. Late events may be stored as historical evidence, not overwrite latest state; mark gaps and reconcile according to 05.

## Adaptive observation windows
Use 5/10/15-second source-time windows, default 10. Use 5s during suspect abnormality or quality concern, 15s after >=60s stable reliable monitoring, otherwise 10s (clinical policy engineering default). Choose next duration at window boundary; define half-open intervals [start,end), retain each original event and coverage. Early safety never waits. Close windows via source watermark or bounded source progress mechanism; document lateness policy, never wait indefinitely for missing vital. Include start/end, duration, event IDs/refs, per-vital samples/summary, missingness, coverage, quality and context/session versions. Missing data must not be zero-filled. Keep raw history for trend and replay; aggregation cannot erase a critical event. Fixed 15s causal encoder frames are separate from windows and owned by 06; no interpolation from future observations.

## Quality and wearable state
Invoke existing artifact rules; immediate safety gets raw and quality evidence, including uncertainty. Joint SpO2 null/zero plus observed HR flatline supports suspected probe removal; do not classify all zero readings as artifact. Keep independent reliable vital evidence active. Maintain attachment, connection and quality as separate dimensions. Authorized simulator presentation state can drive attached/removed media only; isolate from clinical decision input, never use hidden fault labels to improve clinical metrics. BIDMC has unknown physical attachment and no temperature; no synthetic temperature inserted into real replay. Missing stream is a technical issue, not proof of physical removal or clinical recovery.

## Load and delivery
Per-patient/session fair scheduling, bounded queues, priority safety handling, retry with stable IDs and durable processing status. Return actual acceptance status and correlation ID; distinguish queued from persisted. Use 429/503 for capacity or dependency issues as appropriate, with retry guidance; do not silently drop. Expose queue age, depth, failed records and rejected events. Measure source collection, transport, acceptance, safety, window close and decision timestamps independently.


## V4.1 integration revision (Backend V1.1)
Proposed POST /api/v1/observations content-type application/fhir+json, actual Observation body; optional Bundle endpoint only if implemented and validated. Raw JSON is an adapter input, not a replacement API. Use device JWT + HMAC-SHA256 and signed transport headers as in 06/11. Validate JWT and signature, scoped assignment, payload and freshness before state mutation. Atomic nonce/sequence plus durable idempotency: a retry with fresh nonce and identical logical event/hash returns previous receipt; conflict if hash changes. Freshness ±30 seconds on signed request time (configurable), never original measurement time. Record accepted event + outbox atomically; return 202 only once durable. Preserve every per-vital observation identity. Do not expose clinical decisions to producer by default. See 10/11 for queue and adapter details.

# Shared MATLAB/BIDMC source adapter
Proposed interface for Claude; coordinate with producers before wire freeze. MATLAB emits observed four-vital packets; BIDMC emits observed HR/RR/SpO2 only. Adapter converts to separate R4 Observations at source cadence, sends individually or supported validated Bundle. One pipeline. MATLAB never supplies clinical priority, trusted demographics, hidden fault labels or true state. Source adapter is part of existing gateway integration, not new architecture layer.

## Local input
Full registered session key; device_id; packet_id; sequence; source_time_s; measured_at (or derived documented replay effective time); each vital value|null, unit, source quality and absence reason. Preserve zero as observed. Derive stable observation event ID from packet/session/vital (one ID per FHIR resource), and stable FHIR identifier. Use unique increasing transport sequence per session/observation; packet sequence retained separately. Validate mapping and authorized session before submit; server revalidates. For BIDMC retain record ID and original offset including record23 -1, no fabricated temperature or Synthea history. Clinical processing uses source seconds; current request timestamp separate. Never use scenario labels or offline ground truth as clinical inputs.

## Proposed transport
POST /api/v1/observations, application/fhir+json, body actual serialized R4 Observation. Headers: Authorization Bearer device JWT, X-Device-ID, X-Session-ID, X-Timestamp UTC Unix seconds, X-Nonce unique, X-Sequence, X-Key-ID, Idempotency-Key event ID, X-Signature hex HMAC-SHA256. Server derives namespace/subject/variant from authorized session; verifies FHIR subject matches. Source offset/provenance via agreed typed metadata (e.g. signed X-Source-Time-S header), not an unvalidated clinical field. Final Pydantic/transport mapping pending approval. Proposed canonical format UTF-8 newline-joined exact method uppercase, request path, device ID, session ID, timestamp, nonce, sequence, key ID, event ID, source offset string, SHA256 hex of exact body bytes; no trailing newline. Reject unexpected delimiters/header duplicates; all signed fields parsed consistently. Sign bytes actually transmitted; TLS required. Fresh nonce and timestamp on retry, identical body and event ID; preserve logical event sequence. Signature compare constant-time. Token/keys from secure config, never export in logs.

## Acceptance
202 only after durable handoff; prior receipt for identical authorized retry. 401/403 stop/re-auth as applicable, 409 conflict reconcile, 422 malformed correct, 429/503 bounded backoff/jitter and local buffer; no silent loss. Pause replay without advancing source time; reset creates new authorized session. Confirm server mapping, test native FHIR create/read and real-time/accelerated replay. Source event timestamps and latency distinct. Do not report successful HAPI write merely from 202.

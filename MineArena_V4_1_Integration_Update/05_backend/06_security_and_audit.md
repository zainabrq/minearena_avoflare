# 06 | Security, privacy and audit

V4.1 section 15 governs. Proposed implementation defaults must be agreed with existing backend; do not claim deployed security until tested. Use synthetic demo data only. No autonomous clinical actions.

## Trust boundaries
Authenticated producer -> gateway -> internal services -> protected HAPI/state stores; authorized clinician/patient/evaluator -> FastAPI -> scoped operations; browser never accesses HAPI directly. Verify identity and scope before lookup, processing, persistence, subscription, replay or mutation. Separate producer credentials from human sessions and admin roles. Least privilege, deny by default. Patient access limited to own approved information; clinician assigned patients; evaluator synthetic run scope; admin system operations do not automatically grant clinical data access.

## Source integrity and replay
Reuse existing approved scheme. If absent, propose HMAC-SHA256 over an explicitly versioned canonical envelope or exact transmitted body plus method/path, producer ID, event ID, session, nonce and signed transmission timestamp; define unambiguous encoding and verify constant-time. Use secret per producer, protected server-side, key ID and rotation/revocation. TLS required outside isolated local development; signatures do not encrypt data. Bound timestamp skew using wall clock, maintain nonce cache across allowed window, atomic event dedup with durable IDs and payload hash. Reject invalid signature, stale signed transmission timestamp, nonce reuse and unauthorized identity; audit reason without secrets. Identical logical event retransmission with fresh nonce returns prior result. Do not reject historical source recording times as replay attacks. Confirm actual protocol with teammate before coding; do not add alternative parallel auth scheme unnecessarily.

## Human access and transport
Existing secure session or short-lived token scheme; secure HttpOnly/SameSite cookies and CSRF protection where applicable, or appropriately protected bearer credentials. No plaintext passwords, tokens in URLs or frontend bundles, permissive wildcard credentialed CORS, public HAPI or debug routes. Validate WebSocket Origin, authorize subscriptions and recheck expiry/revocation. TLS in deployment, private service networking, protected credentials from environment/secret store. Encryption at rest and key handling according to deployment; local demo limitations explicit. Hash passwords with established password hashing if local auth exists; no custom cryptography.

## Audit record
Append-only logical event with ID, UTC time, actor/producer pseudonymous ID, role, action, authorized scope, correlation/event ID, object reference/version, outcome, reason code, integrity/checkpoint reference. Capture auth failures, unauthorized access, replay/conflict, invalid FHIR, persistence failures/retries, context/rule/model changes, manifest/checkpoint creation, alert creation/ack/resolve, care approval, replay controls and exports. Avoid raw credentials or unnecessary clinical payloads. Protect audit access and retention. Tamper-evident chain may use canonical record digest and previous digest with protected checkpoint/anchor; test mutation detection, do not claim immutability merely from hashes. Log clock and sequence gaps. Separate security events from clinical alerts.

## Threat and failure tests
Cross-patient URL/subscription access, forged subject mapping, producer identity spoofing, signature tampering, stale timestamp, repeated nonce, duplicate logical event, conflict payload, revoked credential, WebSocket origin, injection/XSS, unauthorized care change, audit mutation, sensitive log scan, HAPI public access and simulated overload. Record actual evidence and residual risks. Do not claim production compliance, medical certification or clinically validated security from hackathon tests.


## V4.1 integration revision (Backend V1.1)
Adopt NGINX TLS, strict JWT issuer/audience/algorithm/expiry/nbf/scope/device credential version and revocation. Per-device HMAC-SHA256 exact bytes; use canonical format in 11 with constant-time comparison and key ID. Signed timestamp ±30s proposed, nonce uniqueness, sequence and event/hash dedup, atomic checks and durable acceptance transaction. Protect Redis/Postgres/HAPI and service credentials on private networks; rate/size limits per source, safe backpressure; do not let attack traffic exhaust P0 capacity. Authenticated duplicate retry with fresh nonce must not repeat effects. Device restart creates authorized new session/sequence epoch; reject arbitrary reset. Controlled attacker/defender demo only on isolated synthetic environment, predefined cases and test credentials. Log validation gate, reason, correlation, whether clinical routing/persistence occurred and impact on urgent queue, without raw secrets. Security audit separate from clinical alerts.

To train our digital twin properly, we need more than just the four physiological signals generated by MATLAB. We need information that connects the patient's clinical context, observed physiological behavior, underlying physiological dynamics, expert interpretations and actual future outcomes.

But there is one important distinction in our architecture:

We do not train all four components in the same way.

| Component                | Does it require training? | What it needs                                                                          |
| ------------------------ | ------------------------- | -------------------------------------------------------------------------------------- |
| Manifest                 | No                        | A structured, reproducible representation of the patient's physiological state         |
| Encoder                  | Partially                 | Defined features, normalization statistics and potentially a trainable projection      |
| PINN-ODE                 | Yes                       | Physiological trajectories, governing equations, parameters and prediction targets     |
| Trustworthy Intelligence | Partially                 | Validation data, uncertainty calibration, evidence rules and counterfactual evaluation |

Our goal should be to prepare one unified training dataset from which all four components can obtain the information they require.

## D. Physiological parameters and governing equations

This is the information that makes our model physics-informed rather than simply another time-series prediction network.

We need the MATLAB team to provide the exact equations or mathematical logic used to generate each vital.

| Parameter category     | Required information                                        |
| ---------------------- | ----------------------------------------------------------- |
| Initial conditions     | Initial HR, RR, SpO₂ and temperature                        |
| Individual baselines   | Patient-specific resting values                             |
| Time constants         | How quickly physiological variables respond or recover      |
| Coupling coefficients  | How one physiological variable influences another           |
| External influences    | Activity, recovery, simulated stress and medication effects |
| Deterioration dynamics | How deterioration changes the simulated physiology          |
| Recovery dynamics      | How the physiological state returns toward baseline         |
| Parameter ranges       | Minimum, maximum and default values                         |
| Units                  | Units of every parameter and derivative                     |

For example, an illustrative cardiovascular equation might be:

\\[ \frac{dHR}{dt} = -\frac{HR-HR_b}{\tau\_{HR}} +\alpha_T(T-T_b) +\alpha_A A(t) \\]

Where \\(HR_b\\) is the baseline heart rate, \\(\tau\_{HR}\\) is a response time constant, \\(\alpha_T\\) represents temperature coupling, and \\(A(t)\\) represents activity.

We need equivalent descriptions for the respiratory, oxygenation and thermal dynamics.

We cannot finalize the PINN-ODE physics loss until we understand which physiological equations are actually implemented and which are only assumptions.

If the MATLAB simulator currently generates signals using interpolation or predefined curves rather than mechanistic ODEs, that is acceptable for initial data generation. However, we will need to independently define and justify the governing equations used by the PINN-ODE.

# 4. Information required from the clinical intelligence team

Before we train the PINN-ODE, we need to generate the physiological expert outputs that will form part of the encoder input.

Each expert must process the historical observations using the same rules that it will use during live monitoring.

Six quality features per vital:

| Feature          | Meaning                                           |
| ---------------- | ------------------------------------------------- |
| Present          | Measurement available                             |

| Invalid          | Measurement rejected for physiological estimation |

| Suspect fraction | Suspect observations within the window            |

4 × 6 = 24.

## D. Expert features and masks — 64

The eight features from each of the four experts produce 32 numerical features.

Another 32 masks indicate which expert features are available.

## E. Patient context and masks — 64

The existing 32 context features include age, days since discharge, documented clinical domains, historical conditions, medication information, oxygen personalization, recovery phase, activity and symptom availability.

Another 32 masks distinguish known information from unknown information.

## F. Temporal and baseline features — 16

These represent baseline establishment, baseline freeze status, calibration progress and temporal processing information.

We should avoid letting the model exploit simulator-specific shortcuts. For example, elapsed session time and source type can remain available as operational metadata but should initially be neutralized in the learned model input.

Otherwise, the model might learn that deterioration usually begins at a particular simulator time instead of learning the physiological behavior.

## Encoder normalization

For continuous features, a standard normalization approach is:

\\[ z_i=\frac{x_i-\mu_i}{\sigma_i+\epsilon} \\]

The normalization statistics must be calculated using the training partition only.

We need to save:

```
encoder_schema.json
normalization_stats.json
categorical_mappings.json
feature_masks.json
encoder_version.json
```

### Do we need to train the encoder?

The feature extraction and normalization stages are deterministic.

If we add a learned projection, such as a small multilayer perceptron, its weights can be trained jointly with the PINN-ODE.

There is no need to train a separate large neural network just to encode the manifest.

# 7. PINN-ODE training information

This is the actual neural training component of our digital twin.

## What goes into the model?

At a given time \\(t\\), the model receives:

\\[ Z_t\in\mathbb{R}^{264} \\]

It also receives the estimated current physiological state, applicable parameter priors and recent physiological history.

For example, a proposed five-minute history at 15-second resolution provides 20 historical assimilation frames.

#### One training example

Example configuration: five minutes of history to predict the next five minutes. Future measurements are never included in the input.

## What should the model predict?

The primary prediction targets are the future trajectories of:

\\[ \hat{x}(t+h)= \begin{bmatrix} \widehat{HR}(t+h)\\\ \widehat{RR}(t+h)\\\ \widehat{SpO_2}(t+h)\\\ \widehat{T}(t+h) \end{bmatrix} \\]

Where \\(h\\) represents the forecast horizon.

| Forecast horizon | Priority                |
| ---------------- | ----------------------- |
| 5 minutes        | Primary training target |
| 15 minutes       | Secondary               |
| 30 minutes       | Experimental            |

The model should predict trajectories, not merely a single deterioration label.

The clinical decision system can then interpret those trajectories using clinical rules and trustworthy intelligence.

## Information needed for the loss function

The hybrid model will require multiple training objectives.

\\[ \mathcal L\_{\text{total}}= \lambda_d\mathcal L\_{\text{data}} +\lambda_p\mathcal L\_{\text{physics}} +\lambda_i\mathcal L\_{\text{initial}} +\lambda_b\mathcal L\_{\text{bounds}} +\lambda_r\mathcal L\_{\text{regularization}} \\]

| Loss               | Required information                                             |
| ------------------ | ---------------------------------------------------------------- |
| Data loss          | True or reliable future physiological trajectories               |
| Physics loss       | Governing relationships, equations and physiological constraints |
| Initial-state loss | True or reliable physiological state at initialization           |
| Bounds loss        | Justified state and parameter bounds                             |
| Regularization     | Parameter priors and limits on unnecessary neural corrections    |

### Example data loss

\\[ \mathcal L\_{\text{data}} = \frac{1}{N} \sum\_{i=1}^{N} \left\\|\hat{x}\_i-x_i^{\text{true}}\right\\|^2 \\]

The four vital signs should be appropriately scaled so that HR errors do not dominate SpO₂ or temperature errors simply because of their numerical ranges.

### Example physics formulation

\\[ \frac{dx}{dt} = f\_{\text{phys}}(x,p,u) + f\_\theta(x,z,u) \\]

The mechanistic part represents our selected physiological equations.

The neural residual learns the dynamics that the simplified mechanistic equations cannot adequately represent.

Because the ODE solver already integrates this hybrid equation, additional physics losses should enforce meaningful independent constraints rather than merely repeating the same equation.

## Important information about external influences

If the simulator includes activity, medication effects, oxygen support or other external inputs, we need to know which of those variables will actually be available at runtime.

We cannot train the model using hidden future interventions and expect it to perform similarly during deployment.

For example, if future patient activity is unknown, the forecast should explicitly state its assumption about activity rather than pretending to know what the patient will do.

We need information about when the model is correct, when it is wrong, why it is wrong and how sensitive its predictions are to uncertain evidence.

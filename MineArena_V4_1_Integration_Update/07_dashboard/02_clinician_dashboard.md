# 02 | Clinician workspace

## Navigation and desktop layout
Top-level text nav: Overview, Patients, Clinical alerts, Clinical reports, Evaluation (authorized), FHIR records (authorized), Settings. Workspace switch to patient only for authorized roles; no impersonation by mere selector. Patient detail tabs: Monitoring, Profile, Digital twin, Intelligence, Care plan, History. Preserve selected identity on internal navigation, clear data on identity change. Persistent clinical decision-support disclaimer. Header shows source/session, actual connection and last update, no fake live badge.

### A. Login
Split 45/55 desktop, white entire screen. Left logo, heading “Sign in to Avoflare”, short description, visible form fields from actual auth mechanism, primary sign-in, error/loading/unauthorized states and disclaimer. Right supplied `login_hero` video with white negative space; no text over video. On mobile prioritize form and optional still media. No marketing claims. Auth from backend, no hardcoded credentials in shipped code; demo login only if explicitly enabled and labeled. Successful login route by server role.

### B. Overview / Patients (mandatory 3.6)
At 1440px: page header and search/filter toolbar; one horizontal summary strip with total, Watch, Review, Urgent, interrupted/insufficient counts (not icon cards). Define overlapping monitoring counts separately from mutually exclusive current priorities. Patient table fills remaining width; 10 cohort patients if loaded, independent BIDMC sessions clearly identified. Columns: patient ID and short context, HR bpm, RR /min, SpO2 %, temp °C, partial NEWS2 subtotal/completeness, current priority, unresolved highest alert, monitoring state, last received time. Search by allowed ID/context; sort by unresolved Urgent then current urgency, recency with stable tie-break. Filters source, priority, monitoring, session. No default “all normal” if empty. Rows open exact patient/session/variant. Empty, loading, error, stale, reconnect states. Show actual counts, not hardcoded 10; exclude evaluation-only variants unless selected. Distinguish original Synthea patient from hypothetical overlay and separate BIDMC subjects.

### C. Monitoring detail (mandatory)
Header: avatar if recorded gender maps to existing image, ID, age at discharge if known, clinical context title, source, session, discharge date/status, current concern and highest unresolved alert. No fake name or age. At desktop use left 7/12, right 5/12 columns. Left: four-vital measurement group (2x2), then aligned trend charts with 5/15/30-minute source-time ranges where available, then device media and quality details. Right: assessment, score, active alert, baseline/context. For narrow screens order alert/assessment before media, then vital measurements, charts, device, details. Sticky urgent summary must not cover content.

Vital component: observed value/unit, source timestamp, quality (reliable/suspect/missing), baseline and signed delta (SpO2 percentage points), coverage, accessible chart. Show last valid value separately from current missing state; never interpolate as observed. Time range controls use actual data. Chart mark onset of observed alert and sensor-quality events, not offline ground truth. Use separate chart per unit or clearly labeled small multiples. A real numerical HR trend is not an ECG waveform. Unknown temperature in BIDMC remains missing.

Assessment panel: current priority, concern, reliability and monitoring independently; highest unresolved clinical alert; short evidence-based assessment and recommended human action. Independent safety updates render immediately, not gated on 3D, forecast, HAPI or video. Score panel: “Partial NEWS2-style subtotal”, 0–12 only with all four eligible components, component rows and completeness, scale authorization and oxygen context. For incomplete score show backend subtotal with denominator/coverage explicitly as incomplete, never a full NEWS2 score. Never apply full NEWS2 escalation threshold or compute priority from subtotal. Baseline panel: calibration/established/frozen/resuming, eligible seconds, per-vital reference and deviation, freeze reason, context version. Use actual backend policy, not frontend timer for clinical decisions.

Device panel: use 07 state/media spec; show source, inferred/confirmed attachment, signal quality, last packet time, separate connectivity. No physical wristband claim for BIDMC; show replay source and data quality instead. Confirmed simulated removal visual only from authorized presentation state, not inferred from raw zero alone. Clinical algorithm must not consume simulated fault labels.

### D. Profile
Flat record layout with header/avatar, then sections: selected encounter/discharge, documented conditions with status/date/evidence, medication history with current-use certainty, procedures with verification, allergies (unknown if unavailable), oxygen scale and authorization, care plan and historical vitals. Use context snapshot and references, not duplicate clinical history in manifest. Show clinical cutoff and provenance. Historical vital values are not baseline. P007/P008 do not imply confirmed postoperative status. Beta blocker history not proof of current use. P002-H is hypothetical documented/authorized hypercapnic overlay, isolated from original P002. BIDMC no fabricated Synthea history. Unknown fields visible as “Not documented” or “Unknown” as appropriate. Expand evidence to authorized source reference. No clinical edits unless existing authenticated backend workflow supports them.

### E. Digital twin
White spatial panel, procedural central matte sage state object with four white nodes (HR, RR, SpO2, temp); labels black/green, functional selection, no anatomy. Adjacent textual details. Tabs Observed, Estimated, Forecast: observed reliable measurement and timestamps; estimates explicitly labeled with uncertainty; forecast requires model result and status, primary 5min, optional 15/30min only when available. Actual charts with observed solid, estimate distinct, forecast dashed, uncertainty band and now boundary. No projection if abstained/failed/unavailable; show reason. Experimental forecast cannot independently change priority. Center opens textual manifest inspector: identity/context reference, version/checkpoint, observed/baseline state, relationships, quality, equation set, provisional parameters, evidence refs. Never embed full patient history or offline ground truth. Show model version, estimate time, solver status, uncertainty and limitations. No artificial predictions or confidence. Use accessible textual fallback even when WebGL works. See 07.

### F. Intelligence (seven experts across tabs)
Patient Context Expert summary and four physiology rows on this screen; Medication and Recovery Expert in Care plan. For each physiological expert: measured value/unit/time, component score, baseline delta, slope, abnormal duration, supporting independent domains, reliability, uncertainty, rule/evidence/context refs, limitations. Show “Not evaluated” for missing output. Selecting row opens evidence drawer. Trust section separate quality, context completeness, baseline confidence, model uncertainty, consistency/OOD, abstention and counterfactual results. No aggregate invented trust percentage. Counterfactual branches: original manifest, exclude suspect observation, perturb uncertain measurement/parameters only if backend supports, compare output and uncertainty, explicitly isolated; no change to patient state, no treatment efficacy claim. Optional procedural 3D branch layout; use simple text/table if no results.

### G. Clinical alerts (mandatory)
Two queues clinical and technical, with verification distinguished as backend category. Filters priority and lifecycle, patient, session, time. Active default, sort highest unresolved urgency. Row: patient, clear finding, priority, category, first/last time, lifecycle, evidence freshness. Detail header and three required explanation blocks: triggering reading (value/unit/time/ref), applied rule (ID/version/description), relevant patient fact (with evidence or explicit unavailable). Add trend/baseline, independent safety trigger, reliability, action, limitations and history. “Acknowledge” and “Resolve” separate; resolve requires authorized actor, review, reason and backend eligibility. Confirmation for resolution; show pending/error and server result, no optimistic closure. Recurrence and recovery verification visible; normal packet must not close urgent. Technical probe removal can coexist with true urgent. Accessible status announcement for new urgent, not every vital tick. Do not hide clinical alert under media. If escalation FHIR Flag/CommunicationRequest implemented, display actual resource and delivery status, not fake sent state.

### H. Care plan, reports, history
Care plan: approved tasks, recovery phase/duration, medication schedule with confirmed vs historical distinction, symptom history, Medication Expert recommendations pending clinician approval, Recovery Expert progress. No new prescription or autonomous dose changes; no approved plan means unavailable. Optional clinician approval only actual backend authorized action with audit trail. Reports: backend ClinicalReportV1 summary, period, observed trend, alert episodes, evidence, model limitation, author/status/version; generate/export only if actual endpoint available. History: session-scoped time filter, observations, context/manifest versions, alerts and interventions; FHIR record link; show missing and invalid explicitly. Do not mix current and historical state. Settings: role/account, reduced motion, display units per supported contract (canonical stored units unchanged), connection health; no clinical threshold configuration unless authorized backend supports it.

# 04 | Evaluation and system evidence workspace

Operator-only, white scientific layout. Source of truth `../08_evaluation/` protocol, scenario plan, metrics contract and acceptance tests. Use actual backend run IDs and results. Never populate a report with mock numbers or let offline annotations leak into runtime monitoring. Separate evaluation-only visual ground truth from clinician screens and runtime service.

## A. Replay controls
Page header “Scenario evaluation” and run status. Left setup panel, right timeline and stream summary. Select MATLAB virtual wearable or BIDMC. MATLAB: actual scenario list from 02_scenario_plan.json/backend supported scenarios, patient/variant, seed and duration if supported, rate, speed. Stable, slow deterioration, motion, probe removal, simultaneous fault/deterioration, intermittent and connectivity tests. BIDMC: choose actual record ID among available recordings, real-time or accelerated speed, no fabricated temperature or Synthea context. Start/Pause/Resume/Stop/Reset only supported operations. Disable invalid combinations, show reason; reset creates a new isolated session or backend-confirmed reset, never clears other patient state. Display source time and elapsed wall time separately, source rate and playback speed. Preserve record 13 RR zero and record 23 negative source offset according to actual replay mapping. No manual UI generation of synthetic clinical data; simulator owns samples.

## B. Comparative results
Run both comparator and V4.1 on identical observed data, same exposure and episode policy; backend evaluation owns matching and formulas. Display actual evaluation_id, run IDs, policy/comparator versions, source duration, coverage, warnings. Top comparison table: detected events, missed events, detection lead time, detection delay, false clinical episodes, alerts/patient-day, technical/verification burden. Null/zero denominator show “Not applicable”, pending show “Not run”. Lead time is severe endpoint minus first qualifying alert; negative is late; if no severe endpoint show delay separately. Report sample count, paired comparison only same detected events, avoid hiding misses. Show source-time timeline with first alert per system; ground truth allowed only in evaluation-only results after execution. Stable/artifact-only scenarios should distinguish false clinical alerts and technical/verification. No green victory banner if missed detections increase. Report exposure seconds and connected/valid coverage; small-sample limitation. 2D aligned timelines/bar charts, no 3D chart distortion.

## C. FHIR inspection (mandatory evidence)
Filter by authorized identity, session, source, time, LOINC. List actual accepted/persisted/retrieved observations with status/error. Detail JSON from HAPI retrieval, code/system, subject, effective time, quantity/unit or dataAbsentReason, validation status. Required codes HR 8867-4, SpO2 2708-6, RR 9279-1, temp 8310-5, canonical units /min, %, /min, Cel. Follow actual FHIR profile validation, including any required additional coding. Do not mark stored if only accepted by hot path. Show HAPI queue/persistence/reconciliation separately, not block safety. FHIR compliance numerator and denominator from evaluation; expose missing expected resources and validation errors.

## D. System health and security
Actual connection, ingestion, validation, queue status, HAPI persistence, processing stage latency, error counters and audit evidence from authorized API. Distinguish source/wall timing; p50/p95/p99 with n, hardware, concurrency and speed when measured. No fake live counters. Security events show category, timestamp, outcome, authorized redacted evidence; never secrets, tokens, private keys, unnecessary patient data. No extra security architecture. Model benchmark optional, only actual held-out results, no clinical validation claim.

## E. Reports and exports
Generate report through backend or render verified result contract. Show pending/failed/completed with run provenance. Export actual CSV/JSON or report only if available; no fake downloads. Include method, metrics, per-scenario breakdown, missed events, FHIR validity, explainability completeness, limitations. Follow 08_evaluation report template. Keep UI accessible, no large decorative media, no mock metrics in live mode.
